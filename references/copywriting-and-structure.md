# 文案与规格补充

普通生成只需 [SKILL.md](../SKILL.md) 与自动创建的规格骨架。本文件用于复杂文案、旧规格迁移及显式摘录；不要求整份预读。

## 文案

- 按业务目的归组，通常 1～7 项；小改动无需凑 3 项。所有改动文件都需覆盖，相关文件可跨章节复用。
- 标题保留项目模块与具体动作，如“产品工作区评审：合并重复检查并同时开始试用”。不要写脱离项目的常识句。
- `overview` 一两句说明已知的痛点和改法；不要推断未提供的历史原因。`summary` 概括全局，不重复各章全文。
- 翻译内部自造简称，保留准确的业务名称。每条 `point` 只讲一件事；`copy`/`role` 是点击后抽屉中的补充说明。
- 避免“赋能、组合拳、闭环”等空话；精确禁用词由 `lint_report.py` 维护，不必重复检查脚本源码。
- Prefab 只写名称、路径与已变更/新增/删除状态。重要目标列入要点，不能写内部字段、组件关系或未经证实的效果。

## 精简规格（优先）

```json
{
  "title": "任务队列改动汇报",
  "summary": "任务队列合并重复请求，并同步相关说明。",
  "items": [{
    "module": "任务队列",
    "title": "任务队列：相同请求合并执行",
    "overview": "原先相同请求会重复入队；现在合并为一次执行。",
    "files": ["src/queue/*", "docs/queue.md"],
    "diagram": {"type": "scenarios", "cards": [
      {"title": "重复请求", "before": "重复入队", "after": "合并执行"}
    ]},
    "points": [{"title": "合并相同请求", "files": ["src/queue/queue.py"]}]
  }]
}
```

`files` 支持完整 ID、相对路径与 `fnmatch` 通配符；路径会匹配多个范围中的相同文件，要精确引用一个版本时填写 `working:src/queue/queue.py` 等完整 ID。未匹配选择器报错；渲染和校验使用相同展开逻辑。初始骨架的 `files: ["*"]` 只是单章起点，多章时按业务调整。

## 原有规格与摘录（按需）

原有 `fileIds` 和 `points[].diffs` 仍然支持，既有报告无需迁移。要点也可同时提供 `files` 和详细 `diffs`；相同文件不会重复展开。模板会自动选择改动位置，通常不必手写行号。

```json
{
  "fileIds": ["working:src/queue.py"],
  "points": [{
    "title": "合并相同请求",
    "copy": "抽屉顶部的补充说明。",
    "diffs": [{
      "file": "working:src/queue.py",
      "role": "队列入口合并重复项。",
      "before": [{"line": 25}],
      "after": [{"line": 25}]
    }]
  }]
}
```

摘录行号必须来自本次采集的对应侧快照，不手抄源码；代码抽屉仍由渲染器保留受影响操作的完整签名与方法体。Prefab 不允许摘录。

## 模板已负责的排版

首屏标题/统计/总括/模块索引 → 章节 `overview`/图示 → 要点核心文件/折叠外围文件。文件树覆盖全量文件，抽屉桌面为 `80vw`、手机接近全宽；不要在规格里重写这些 HTML，也不重复堆叠总表或长解释。默认模板复用只做静态校验，不要求窄屏检查。
